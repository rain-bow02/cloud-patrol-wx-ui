# 物业智能巡更 H5

巡更移动端独立仓库：`rain-bow02/cloud-patrol-wx-ui`。PC 菜单、管理页面及其权限定义仍在 `jetlinks-v2/cloud-patrol-ui`，后端仍使用物业仓库中的巡更服务。H5 独立安装、运行和发布，不依赖 PC 源码或 SaaS 桌面布局。

## 开发与构建

使用 Node.js 22.18 或更高版本：

```bash
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

开发服务固定使用 `127.0.0.1:9301`，`/api` 代理到本地 9300，继续复用现有巡更后端及公共服务代理。9300 可将 `/patrol-h5` 代理到 9301。生产产物为 `dist/`，发布到站点 `/patrol-h5/`，并保留同源 `/api` 网关代理。

`mobile/` 保存页面、登录、扫码、离线和宿主适配代码；`api/types.ts`、`model/`、`locales/` 为本仓库拥有的接口类型、纯业务计算及语言资源，初始版本从 PC 仓库迁出。后续接口变更需同步兼容两端；这里没有跨仓库源码导入或共享 node_modules 要求。

## 应用入口与登录

APP 完成登录、选择项目及具体应用后，从该应用打开 H5。H5 不发现或切换应用，不按模板 ID 或应用名称识别应用，也不要求普通成员有模板查询权限。

浏览器调试使用带应用 ID 的明确入口：

```text
http://localhost:9300/patrol-h5/?applicationScope=<应用ID>
http://localhost:9301/patrol-h5/?applicationScope=<应用ID>
```

浏览器登录只填写应用账号、密码及需要时的安全验证，账号原样提交（包括账号自身已有的后缀），不要求输入项目编码。公开登录请求不带 PC token、应用 Scope 或租户域名；登录后以本人 token 和入口应用 Scope 调用 `/authorize/me` 校验实际授权。业务请求带 `X-Access-Token`、`X-Asset-Scope: business_application:<ID>`，按所选业务项目携带 `X-Patrol-Project`，不从旧会话继承 `X-Tenant-Domain`。

会话只存当前标签页 sessionStorage。刷新重新核验应用，401 清理会话，403 保留登录并显示权限问题。缺少巡更业务权限不等于没有应用成员资格，页面提示由管理员配置，具体操作仍由后端校验。裸 `/patrol-h5/` 显示从具体应用进入的提示，不猜测唯一应用或恢复到历史应用。

`mobile/public/config.json` 仅配置 `title` 和同源 `apiBase`，不配置模板 ID、应用 ID 或项目编码。测试、UAT、生产可复用构建产物。

登录后的“所属项目”是物业业务筛选，与登录项目编码不同。首次只加载授权项目树，只能选择项目节点，普通组织灰色不可选；未选或清空时不加载统计、任务、点位和记录。APP 的平台项目上下文不直接充当物业业务项目。

## APP 宿主契约

`mobile/transport.ts` 定义巡更侧 `PatrolHost` 契约，不假定初版 APP 已实现。宿主需在 H5 加载前提供 `window.patrolHost`；也可用 `?mode=app` 明确宿主模式，缺少 Bridge 时显示错误，不退回浏览器登录。

- `context(): Promise<MobileContext>`：提供 `userId`、`applicationId`，可附 `environmentId`、平台 `projectId`、姓名及当前应用 `permissions`。启动等待上下文，超时显示重试；每次业务请求前后核对身份与应用，拒绝迟到的旧数据。
- `request(path, method, body, options?)`：接受巡更相对路径和 GET/POST/PUT，由宿主绑定登录态与应用 Scope，`options.projectId` 转为业务项目头。支持原样 FormData，返回已解包业务结果，失败抛出携带状态的 `MobileError`；写入不自动重试。
- `back?()`：可选，首页返回交给宿主关闭页面。

宿主模式不读浏览器登录配置或凭据。会话过期、身份或应用变化会终止当前上下文，并提示返回 APP。真机 Bridge、multipart、存储隔离及登录过期仍需 APP 团队接入验收。

HTML 使用 viewport-fit=cover；宿主可提供 `--patrol-app-safe-top` / `--patrol-app-safe-bottom`。业务页保留浏览器历史，提交中阻止页面内返回；原生直接销毁 WebView 仍需宿主协商。软键盘适配优先 VisualViewport，旧 WebView 回退窗口 resize。

## 本版功能

- 巡更管理首页：参考原小程序提供可巡更点位、冷却中、今日已完成、漏检数量四项统计，以及巡更打卡、点位管理、打卡历史、漏检申报入口。四张统计卡均可点击：前三项进入本人任务并按同一状态口径筛选，支持返回全部；完成数和完成列表均按任务归属日统计，保留已经结束的当日时段。前三项沿用原后端按角色和真实时段任务计数的口径，同点位多个任务在列表合并展示、详情保留各时段。漏检卡片进入近7日漏检页；失败显示未加载，不冒充零条。
- 巡更打卡：展示“全员 / 我的”、分类与名称筛选、五列点位网格和状态图例；小于360px时采用四列。只展示当前时间窗，点位详情保留对应巡更角色与任务，避免同一点位有多个任务时随意提交。
- 点位管理：按项目、分类和名称查询及分页；新增、编辑名称、编码、位置、状态、标签和备注，编码留空由原后端自动生成或保留。所属项目使用平台已过滤的树，普通组织不可选；点位新增沿用当前选定项目，表单中不切换项目。已存在点位的分类只读展示，H5编辑不开放关联、取消或修改分类；PC独立关联操作保持原业务规则。二维码可查看及保存。巡更角色、全员巡更、点位等级和标准配置复用现有点位配置接口，不创建第二套执行资格规则。
- “我的”显示本人巡更角色；“全员”显示当前有权访问计划的点位，其他巡更角色任务可查看但不可提交。点位可巡、冷却中、已完成使用真实任务状态，无资格、停用或非班次保持不可执行。
- 检查：使用任务保存的标准快照填写选项、精确数值、文本、图片；支持参考说明、范围和例图。
- 提交：校验必填及必需图片，后台重新校验成员、资产权限、巡更角色、班次、时间、次数和冷却间隔。
- 打卡历史：默认查询本人记录。具备点位和执行记录查询权限时，可切换项目记录并按巡更人筛选；此模式复用PC执行记录查询接口及计划资产授权，不修改移动端本人接口。支持日期、分类、等级、名称筛选，分页查看实际答案、异常标红、图片及备注。提交写入现有执行记录表，PC 查询同一份记录。
- 上传：现有巡更证据附件 API，JPEG/PNG/WebP、单张最大5MB，每项一张；文件选择不能证明现场拍摄。
- 扫码：支持 PC 生成的点位 UUID 二维码。选择本地二维码图片，通过随包的 jsQR 在本机解码，不上传图片、不调用摄像头或原生扫码；只查询当前应用授权任务，过滤非当前时段、无资格、冷却中及已完成任务。一个可提交任务进入检查表，多个巡更角色任务先选择；二维码不授权、不自动提交、不解析外站链接或旧硬件 NFC 编码。

“离线作业 → 离线模式”已支持联网下载今日本人任务与检查例图、本机填写和保存照片、同步中心手动上传。数据按应用/员工/所属项目隔离，使用IndexedDB保存真实Blob，不保存登录令牌。NFC提供编码演示，真实碰卡、定位打卡和经纬度管理暂不接入。正式 APP Bridge 仍待对接。普通输入草稿只保留在页面会话；待确认提交另外保存在当前标签页的 sessionStorage，刷新后可恢复原请求号和请求体，须手动重试。切换项目/应用/用户会阻止继续提交，不把旧用户的待确认请求带给新用户。

## 权限与业务边界

沿用 PC 的菜单授权和后端应用、项目、资产权限，不建立另一套业务角色或执行规则。普通员工需要有效员工身份、应用成员资格、相应资产范围及角色/排班执行资格。

| 操作 | 功能权限 |
| --- | --- |
| 任务与分类 | `patrol-task:query`、`patrol-category:query` |
| 本人记录、图片 | `patrol-execution:query`、`patrol-attachment:query` |
| 提交结果 | `patrol-execution:submit` |
| 上传图片 | `patrol-attachment:save` |

后端继续校验时段、次数、冷却、任务版本和请求幂等。点位管理等额外操作按当前应用真实权限展示，前端隐藏按钮不替代后端校验。排班日历不显示 H5 入口，PC 的手机巡更入口继续打开同一 `/patrol-h5/` 地址。

## 部署

将独立构建的 `dist/` 发布到运行站点的 `/patrol-h5/`。与 PC 分开构建发布，不再从 `cloud-patrol-ui/dist-mobile/` 取产物。`config.json` 及登录、验证码接口必须可公开访问，业务接口保留认证。无需修改 SaaS 平台源码；仅更新 PC 产物不会更新 H5。

## 移动端视觉

独立登录页和巡更首页使用浅蓝背景、白色卡片与本地 `assets/patrol-scene.svg` 插图；统计仍使用原有时段口径，首页保留四项统计跳转和四个业务入口。“可巡更点位”和“冷却中”进入同一份当前时段点位列表，分别显示可巡更、冷却和已完成状态；“今日已完成”保留完成任务筛选，包含已结束时段。点位页仅保留扫码入口、点位筛选及状态图例，不再提供页头记录、漏检明细或顶部状态筛选栏；历史和漏检由首页入口进入。图片通过 Vite 导入，支持 `/patrol-h5/` 子路径，不依赖外部图片服务。

列表筛选参考老巡更采用双列紧凑布局，历史保留分类、等级、点位名称、日期范围和有权限时的巡更人筛选；点位管理、漏检列表同步压缩控件间距。项目筛选横向排列。点位页使用白色卡片“扫一扫”入口，继续选择本地二维码图片识别，不调用摄像头。首页移除统计口径描述。

## 图片与NFC编码演示

检查例图、已上传图片和巡更记录中的图片自动显示缩略图，点击放大；读取仍经过原附件接口。点位管理以对齐字段显示所属项目、点位分类等信息，编辑既有点位时分类只读，新建时仍选择分类。

点位页提供“NFC巡更演示”：输入点位绑定的NFC编码，由移动任务查询的可选 `nfcCode` 字段匹配。它只收窄当前应用及项目有权读取的任务；未具备员工资格、角色/排班资格、有效时段或处于冷却中的任务不能执行。此入口不调用手机读卡器，真实NFC碰卡仍待APP适配；发布时需同步部署支持该字段的巡更后端。

## 离线演示步骤

1. 从带 `applicationScope` 的应用入口登录并选择有本人任务的所属项目，从首页进入“离线模式”。
2. 联网点击“下载今日任务”，确认缓存时间和任务数量。任务标准快照及例图全部读取成功才替换缓存，下载失败不覆盖原缓存或队列。
3. 打开“离线作业”开关，可保持联网演示，也可真正断网；此工作区不发送业务查询、图片上传或打卡。保持当前页面打开，选择有效时段任务、填写检查、选择照片，再“保存到本机”。保存成功才进入“待同步”，不计入在线完成次数。同一时段有未确认记录时不重复采集。
4. 联网并关闭开关，在“同步中心”点击“同步待上传记录”。先上传照片并保存回执，再持久化最终请求并提交。超时重试沿用相同请求号、答案、采集时间及已上传附件ID；多标签页通过浏览器Web Locks避免并发同步。
5. 同步成功展示服务器记录、原离线采集时间和照片；失败保留答案和照片及具体原因。过期、权限撤销、角色/排班、次数、冷却等仍按现有后端接收时校验，不因客户端采集时间放宽。演示应在任务有效时段内联网同步。已同步任务需联网更新缓存再采集。

本版支持已打开并登录页面中的离线作业，以及联网重新进入后的本机队列恢复；未实现Service Worker页面壳缓存或断网冷启动/刷新，也不缓存登录凭据供离线登录。浏览器存储被用户清除会丢失本机未同步数据；隐私模式或空间不足时保存明确失败。切换用户/应用/项目不会读取其他身份的离线数据。
